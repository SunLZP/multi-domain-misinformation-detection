# Evidence behind the preprocessing choices

Reviewed 24 October 2026. Sources below are dataset papers and authors' repositories. The implementation here is a new preprocessing utility, not a reproduction of any one paper. Generic fake-news tutorials using other corpora were not treated as evidence for these two datasets.

## What other researchers actually did, and why

| Study / project | Dataset use and preprocessing | Purpose and consequence for this project |
|---|---|---|
| Pérez-Rosas et al., COLING 2018 | Introduced FakeNewsAMT and Celebrity. Extracted TF-IDF unigrams/bigrams, punctuation, readability, LIWC and syntax features. | They investigate deception-related writing patterns. Blanket punctuation removal would erase a feature family they evaluate. Keep raw article structure and lightly normalized text. [Paper, §4](https://aclanthology.org/C18-1287.pdf) |
| Bodó, 2020 | The author's repository supports AMT, separate title/body/combined text inputs, bag-of-words weightings, unigram/bigram variants, a modified tokenizer, feature selection and neural models. | Its experimental design compares representations rather than treating one cleaning recipe as universal. Keep title and body separately available; leave feature fitting to the training stage. [Author's repository](https://github.com/miafranc/fakenews2020) |
| Leite et al., PASTEL | AMT is one of its supporting datasets. The input contract separates title and body, with an article ID and a binary misinformation label. Its workflow extracts LLM credibility signals, consolidates them, then trains/evaluates a weak-supervision label model. | This is a different task pipeline from a TF-IDF baseline. Our raw export now retains title and body, but does not claim to compute those credibility signals or reproduce PASTEL. [Author's repository and input schema](https://github.com/joaoaleite/PASTEL#reproducing-the-paper) |
| Augenstein et al., EMNLP 2019 | MultiFC uses fact-checking website domains and different native rating spaces. The paper describes removing verdict text from claims, handling duplicates and creating label-stratified splits. It deliberately avoids one global rating scale. | Keep original source identity and ratings; separate claim text from fact-check metadata. Our exact-text overlap audit is additional validation of the downloaded release, not a claim to reproduce their original cleaning. [Paper, §3–4](https://aclanthology.org/D19-1475.pdf) |
| Glockner et al., EMNLP 2022 | Uses a richer MultiFC distribution and source-specific Snopes/PolitiFact experiments. It detects evidence leakage with URL/content patterns. Repository configurations distinguish claim-only, evidence-only and combined inputs; include lowercase and 512-token settings for BERT experiments. | Field selection and evidence leakage are methodological choices, not just text cleaning. We export claim-only model input and retain verdict-bearing metadata only in audit CSVs. We cannot run the paper's evidence analysis without its evidence distribution. [Repository](https://github.com/UKPLab/emnlp2022-missing-counter-evidence), [paper](https://aclanthology.org/2022.emnlp-main.397.pdf) |
| Karisani & Ji, NAACL 2024 — your reference | The paper assigns topic domains through Google Content Classification with a manual category mapping. It describes mapping True to Support and the remaining ratings to Refute, and selecting two evidence documents per claim. The repository publishes derived topic-domain data, not the original CodaLab schema. | Their binary mapping changes the task and should not silently become fake/real ground truth here. Reproducing their domain-adaptation experiment requires their released domain assignments/data and evidence, not guessed domains from CodaLab source codes. [Paper, Appendix A](https://aclanthology.org/2024.naacl-long.124.pdf), [reference repository](https://github.com/p-karisani/domain-adaptation-datasets-for-fact-checking) |

## The three meanings of domain

- AMT: topic, such as education or sports.
- Original MultiFC: fact-checking source, such as Snopes or PolitiFact.
- The reference project's MultiFC: five derived topics (Arts, Business, Misc, Politics, Sensitive).

The reference README totals 25,229 claims across its five MultiFC topics and encodes 0=Refute, 1=Support. Our binary exports for both AMT and MultiFC use 0=real, 1=fake. Those numeric meanings run in opposite directions if treated as a binary truthfulness scale. Never concatenate the two releases by numeric label alone. This project does not download or substitute the reference data.

## Decisions implemented here

1. Preserve the decoded original as text_raw. Apply NFC and whitespace normalization to text. Preserve case, punctuation, numbers, negation and stopwords. Title/body separation in AMT uses the first line as the title and subsequent lines as the body, a file-layout heuristic that is documented rather than semantic parsing.
2. Keep model-dependent transformations for later. For a bag-of-words baseline, TF-IDF unigrams/bigrams are a justified candidate, not a proven optimum for this project. Fit its vocabulary/IDF only on training data. Punctuation-aware variants can be compared using training/development data. For a transformer, use the tokenizer matching the chosen checkpoint; do not substitute whitespace word counts for token counts or prescribe universal truncation.
3. Preserve full original membership/order in CSV audit exports. Machine-consumable JSONL removes empty claims explicitly and contains only the approved feature text, label and grouping metadata. Label/group fields are targets/splitting information, not additional text features.
4. Preserve two native-label MultiFC audit profiles: official membership excluding empty claims, and a derived profile also removing heldout exact-text matches to earlier partitions (train, then dev, then test). Within-split duplicates remain; semantic near duplicates are untested. The latter profile changes the evaluation set and must not be presented as the original benchmark.
5. Keep AMT unsplit by default. An optional seeded split puts 32/4/4 filename pairs per topic into train/dev/test, yielding 384/48/48 articles. It is a new convenience split, not the paper's evaluation. Pair IDs remain filename-based candidates, not manually verified semantics.
6. Stop on corrupt inputs or schema errors. On output I/O failure only, attempt a stable results folder outside the project automatically. Publish a success manifest last, with hashes verified by the next-stage loader.

These are evidence-informed engineering choices. No run proves article factuality, semantic pair equivalence, or the absence of all leakage. Report class imbalance, actual split counts, exclusion policy and label semantics alongside any later metrics.


## Binary harmonisation added for this project's two-class task

The original MultiFC release intentionally keeps source-specific rating spaces. Its paper does not prescribe this project's binary mapping. Native exports retain that information; a separate, default binary profile harmonises ratings without changing the source ZIPs. AMT binary exports use the same schema. Both label and label_id are integer 0=real, 1=fake; original_label and domain remain separate.

The project uses a **majority-veracity** convention: mostly true/correct goes with real, mostly false/fiction with fake. These class names are shorthand for the chosen groups; the real class therefore includes qualified truths. Half-true and mixtures have no single binary target under this convention and are excluded. Unproven does not mean false. Promise fulfilment and position changes measure a different construct and are excluded. Unreviewed labels are excluded rather than guessed. This choice narrows the task and can introduce selection bias; it does not guarantee higher accuracy.

The mapping is an explicit allowlist for each source. Literal clearly equivalent labels (true/accurate/correct/verified/fact and false/incorrect/fiction/fake) are reviewed in their original source context, including publisher prefixes. Ambiguous attribution, scam, satire, colour, baloney and Pinocchio ratings are not automatically forced into binary classes. GossipCop uses only endpoints: original 0=fake, 10=real; the binary target encoding reverses those endpoints. The code never treats every original numeric 0 as a real target.

Evidence and boundaries:

- [Original MultiFC paper, Appendix Table 10](https://aclanthology.org/D19-1475.pdf): source codes, rating inventories and heterogeneous label spaces. This anchors the exact released strings; it does not establish every mapping as a publisher-endorsed binary rule.
- [PolitiFact's methodology](https://www.politifact.com/article/2018/feb/12/principles-truth-o-meter-politifacts-methodology-i/): distinguishes true, mostly true, half true, mostly false, false and pants on fire, as well as separate position/promise measures. [Lee et al., 2023](https://misinforeview.hks.harvard.edu/article/fact-checking-fact-checkers-a-data-driven-approach/) provides a precedent for grouping True/Mostly True and False/Mostly False in Snopes/PolitiFact binary analysis. Applying majority groups to additional sources is our project policy, not a claim that the study validated all 26 sources.
- [Africa Check's ratings](https://africacheck.org/how-we-fact-check/how-we-rate-claims), [Check Your Fact's methodology](https://checkyourfact.com/methodology/) and [FactCheckNI's rating explanation](https://factcheckni.org/articles/news/for-your-consideration-factcheckni-verdict-ratings/): distinguish accurate/incorrect judgments from mixed or unsupported claims. Treating mostly-correct as real is explicitly our majority policy.
- [Truth or Fiction's ratings](https://www.truthorfiction.com/fact-check-ratings/): separate truth/fiction from mixed and unresolved categories. Mostly truth/fiction grouping follows the stated project policy.
- [Voice of San Diego's rating definitions](https://voiceofsandiego.org/category/fact/): supports interpreting its false and huckster-propaganda verdicts as false; stretch, barely-true and misleading ratings are excluded here.
- [FakeNewsNet authors' dataset paper](https://www.cs.emory.edu/~kshu5/files/FakeNewsNet_big_data.pdf): describes GossipCop's 0–10 scale running from fake to real. Only its endpoints are used here; intermediate thresholds are not inferred.

On this exact release, the binary exports retain 24,489 rows (70.12%): train 19,610, dev 2,445, test 2,434. They retain 23 sources, excluding abbc, huca and pose entirely. Five retained training sources (bove, clck, farg, vees, wast) contain only fake-class examples. Some small sources lack either class in heldout data and bove has no retained test row. Domain coverage is therefore not equivalent to balanced domain knowledge.

The 10,435 exclusions are: mixed/partial 4,258; promise/position 1,606; uncertain/insufficient evidence 2,126; outside reviewed rules 2,342; time-dependent 79; empty 3; duplicate in an earlier original split 21. These reasons are mutually exclusive, in the code's documented precedence. binary_mapping.csv gives all 160 observed source/rating decisions; binary_excluded.csv accounts for every excluded row. Conflicting binary targets for identical normalized text within a split are also checked; none occur among eligible rows in this release. All originals remain in the native audit CSVs.

The binary profile preserves retained rows' original train/dev/test membership and order. Exact text overlap is removed from heldout partitions against earlier original partitions, without using test labels to alter training. This is a new, filtered task and must be reported as such; its metrics cannot be directly compared with a full native-label MultiFC benchmark. No semantic near-duplicate removal is claimed. Text alone is the feature; original_label, binary targets, group IDs and verdict metadata must not become input features. Source domains remain available for evaluation, not as invented topic labels.
